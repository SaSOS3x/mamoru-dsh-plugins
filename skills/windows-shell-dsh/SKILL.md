# Оболочка DSH на Windows: PowerShell 5.1, python.exe, JDK

Инструмент `pwsh` в DSH на Windows запускает **Windows PowerShell 5.1** (не PowerShell 7 и не
Git Bash), а `python`, `java`, `javap` это родные Windows-программы. Ловушки лежат на стыке:
PowerShell 5.1 не умеет половину современного синтаксиса, консоль и файлы расходятся по
кодировкам, у командной строки лимит, а инструмент показывает код возврата, которому не всегда
можно верить.

Основное проверено на этом ПК 2026-11-02 (DSH, Windows PowerShell 5.1.26100, Python 3.14.7,
JDK 21.0.8 и 17); пункты без пометки взяты из журналов проектов DeceasedCraft и Space Journey
(2026-10), то есть из Claude Code, и в DSH отдельно не перепроверялись. Непроверенное помечено.

Граница с `windows-shell-dev`: тот навык про написание и отладку файлов .bat/.cmd, этот про то,
как агент запускает команды.

## Порядок работы
1. В новом проекте первой командой: `python scripts/env_probe.py [папка со скриптами]`. Строки WARN
   это ловушки, которые сработают именно здесь (кодировки, python3, JDK, имена модулей в указанной
   папке). Код возврата 0 и при WARN: это отчёт, а не проверка (на обычном ПК с Windows какой-нибудь
   WARN есть всегда), поэтому читай строки WARN.
2. Скрипт длиннее 5 строк или с `\`, `'`, `"` внутри: напиши файл инструментом `write`, потом
   `python путь/к/файлу.py`. Правка существующего файла: `edit`, не питоновский replace. `edit` и
   `write` отказывают, если файл не прочитан в этой сессии через `read` или изменён после чтения;
   после сжатия контекста перечитывай файл и правь через `edit`, а не через `Set-Content`.
3. Все пути для python/java: `C:/Users/...` (прямые слэши, с буквой диска). PowerShell понимает и
   обратные, но в аргументах Java-программ прямые безопаснее.
4. Результат оценивай по тексту вывода и по наличию файла, не по коду выхода (ловушка 5).
5. Java: нужный JDK по полному пути; длинный classpath через файл (ловушки 10-11).
6. Всё новое, что стоило больше двух попыток, допиши в этот навык через skill-forge (журнал, потом
   предложение).

## Ловушки: симптом, причина, что делать

1. **`&&` и `||` не работают (ошибка разбора).** В PowerShell 5.1 это не операторы, а синтаксическая
   ошибка: «токен "&&" не является допустимым разделителем операторов» (проверено 2026-11-02).
   Вся команда не выполняется, даже её начало. Делай: два отдельных вызова инструмента; или `;`
   плюс явная проверка `if ($LASTEXITCODE -ne 0) { ... }`; или `-and`/`-or` для выражений. Тернарника
   `? :`, оператора `??`, `Join-String`, `-Parallel` тоже нет: это PowerShell 7.

2. **`cd` не сохраняется между вызовами.** Каждый вызов инструмента - новый процесс (проверено:
   после `Set-Location C:\Windows` следующий вызов снова в папке сессии). Делай: передавай инструменту
   параметр `workdir`, а не `cd`; или строй полный путь в каждой команде. Внутри одной команды
   `Set-Location` действует до её конца.

3. **Кодировка записи файлов.** В 5.1 `>` и `Out-File` пишут UTF-16LE с BOM, а
   `Set-Content -Encoding utf8` - UTF-8 **с** BOM (оба проверены 2026-11-02: `FF FE ...` и
   `EF BB BF ...`). Исходники и конфиги проекта правь через `edit`/`write`. Если файл пишет сам
   скрипт PowerShell, для UTF-8 без BOM и с CRLF:
   `[System.IO.File]::WriteAllLines($p, $lines, (New-Object System.Text.UTF8Encoding($false)))`.
   Чтение наоборот: `Get-Content` без BOM в 5.1 читает файл как ANSI и показывает кракозябры
   (`привет` -> `РїСЂРёРІРµС‚`, проверено); спасает `-Encoding UTF8` или `[System.IO.File]::ReadAllText`.

4. **`2>&1` у нативной программы даёт ошибку даже при успехе.** В 5.1 строки stderr становятся
   объектами ошибок с `NativeCommandError`, и команда выглядит упавшей, хотя `java -version`
   отработала (проверено 2026-11-02). Делай: не склеивай потоки у нативных команд; проверяй
   `$LASTEXITCODE`, а для java - `BUILD SUCCESSFUL` / `FAILURE`.

5. **Код выхода врёт.** Инструмент печатает `[exit code: N]` по коду процесса, а PowerShell
   выставляет `$LASTEXITCODE` только нативным программам и не сбрасывает его у командлетов: после
   `Get-ChildItem ... -ErrorAction SilentlyContinue | Select-Object` с пустым выводом инструмент
   показал `[exit code: 1]`, хотя ошибки не было (проверено 2026-11-02). Цепочка через `;` даёт код
   последней команды, ошибка командлета без `-ErrorAction Stop` вообще не влияет на код. Делай:
   читай вывод на `Traceback|Error|Exception|No such file|not recognized|cannot|denied`, проверяй,
   что нужный файл создан и не пуст; в скриптах ставь `$ErrorActionPreference='Stop'` и явный
   `exit 0`/`exit 1` по настоящему признаку успеха. Обратный случай - robocopy: код 1 значит
   «скопировано», ошибка от 8 и выше.

6. **Ошибка командлета не останавливает скрипт.** Без `-ErrorAction Stop` (или
   `$ErrorActionPreference='Stop'`) `Copy-Item`, `Get-ChildItem`, `Remove-Item` пишут ошибку и идут
   дальше, а код возврата остаётся 0. Делай: `-ErrorAction Stop` в критичных местах и проверка `$?`
   сразу после команды.

7. **Кодировка python (cp1251).** Без настройки stdout это cp1251: `print('\u2192')` даёт
   UnicodeEncodeError (проверено в DSH 2026-11-02; с `python -X utf8` печатает стрелку). `open()`
   без `encoding=` тоже читает в cp1251: UTF-8 файл читается МОЛЧА с мусором. Всегда
   `encoding='utf-8'` в open/read_text/write_text; для вывода - `python -X utf8` или
   `sys.stdout.reconfigure(encoding='utf-8')`. Задать `PYTHONIOENCODING` можно в профиле DSH или в
   `AGENTS.md` проекта, но только с согласия пользователя.
   **Конфликт с `-I`:** `python -I` игнорирует ВСЕ переменные `PYTHON*` и пакеты пользователя
   (`pip install --user`): `ModuleNotFoundError: No module named 'PIL'`. Где нужен `-I`, пиши
   `python -I -X utf8`. `-I` нужен там, где его требует окружение: скрипт читает файлы, которые
   агент сам скачал или распаковал из сети. Файлы проекта и пользователя к ним не относятся, такие
   скрипты запускай без `-I`.

8. **`python3` это заглушка Microsoft Store.** На этом ПК `python3` - `WindowsApps\python3.exe`
   (проверено), печатает `Python` и ничего не делает. Вызывай `python` (здесь 3.14.7 из
   `C:\Python314`). Если скрипту нужен именно тот python, что идёт с DSH (3.12 с numpy, pandas,
   openpyxl, python-docx), возьми его путь инструментом `load_workspace_dependencies` - он отдаёт
   абсолютные пути к bundled python и библиотекам. Не хардкодь путь `F:\AI\resources\...`.

9. **Имя скрипта = имя модуля stdlib.** `json.py`, `struct.py`, `types.py`, `random.py` рядом со
   скриптом или в текущей папке (даже для `python -c`) перекрывают настоящий модуль:
   `AttributeError: module 'json' has no attribute 'dumps'`, сломанный `zipfile`. Не называй так
   черновики; `python -I -X utf8` игнорирует и папку скрипта, и текущую.

10. **Лимит командной строки ~32 тыс. знаков.** `java -cp <37 тыс.>` даёт `Argument list too long`
    (код 126). Для `java` и `javac`: `@файл` с аргументами или переменная `CLASSPATH` (37 тыс.
    прошло). У `javap` `@файл` НЕ работает (`class not found: @cp2.args`):
    `python scripts/classpath_jar.py cp.jar @jars.txt` собирает jar с `Class-Path` в манифесте,
    дальше `javap -cp cp.jar класс` (проверено: 522 записи, 70 тыс. знаков манифеста).
    Несуществующий путь в списке останавливает сборку (код 1, jar не пишется): так устаревший
    `jars.txt` не даёт молча неполный classpath. Если старые строки в списке ожидаемы, добавь
    `--skip-missing`, тогда будут только предупреждения.

11. **Не тот JDK.** `JAVA_HOME` и `java` на PATH могут указывать на разные JDK; здесь `java` = 21,
    `javap` и `jar` = 17 (проверено). Класс, собранный `javac` 21, не запускается через
    `$JAVA_HOME/bin/java`: `UnsupportedClassVersionError ... 65.0 ... up to 61.0`. Gradle/Maven
    берут `JAVA_HOME`. Делай: полный путь `"C:/Program Files/Java/jdk-21/bin/javap.exe"`, для
    сборки `JAVA_HOME="C:/Program Files/Java/jdk-21"`; перед javap прогони `env_probe.py`.

12. **Русский текст ошибок PowerShell приходит искажённым.** В выводе инструмента сообщения вида
    «Не удается найти путь» иногда видны кракозябрами (наблюдение 2026-11-02, механизм не выяснен).
    Не суди по тексту: смотри `FullyQualifiedErrorId`, тип исключения, код и наличие файла. Для
    машинного разбора печатай свои английские маркеры (`RESULT=FAIL reason=...`), а не полагайся на
    текст ОС.

13. **Песочница DSH.** Запись идёт только в рабочую папку сессии (`workspace-write`), остальное
    даёт `[sandbox: file access denied ...]` - это решение политики, а не сбой команды: не обходи
    его другим способом, а скажи пользователю и попроси расширить доступ. В режиме `read-only`
    PowerShell работает в ConstrainedLanguage: недоступны вызовы .NET (`[System.IO.*]::`),
    `Add-Type`, COM и рефлексия. Удаляй только то, что создал сам, отдельной командой с литеральным
    путём в двойных кавычках (`Remove-Item -LiteralPath "..." -Recurse -Force -Confirm:$false
    -ErrorAction Stop`); путь с апострофом - только в двойные кавычки.

14. **Фоновые задания.** `run_in_background: true` возвращает id сразу и не имеет таймаута: пока
    задание не снято `job_kill`, оно живёт; `timeoutMs` действует только у команды на переднем
    плане. Забирай вывод через `job_output` (не опрашивай в цикле), в конце прогона печатай маркер
    (`DONE`/`FAIL`) и жди именно его. Долгий прогон (часы) запускай отдельным процессом
    (`Start-Process`) и следи за файлом-маркером.

15. **CRLF и LF.** Python на Windows сам пишет CRLF: `open(p, 'w')` и `Path.write_text` переводят
    `\n` в `\r\n`. Файл, который должен остаться LF (скрипт для `workflow`, конфиг игры), пиши через
    `open(p, 'w', newline='')`. Считать окончания строк по байтам, а не через `grep -c $'\r'`
    (в Claude Code это давало 0 на CRLF-файле): `python scripts/eol.py файлы` (CRLF / LF / CR, BOM,
    MIXED); файл с байтами NUL он называет BINARY.

16. **Мелочи инструментов.**
    - `write`/`edit` не создают родительскую папку молча в некоторых режимах: сначала создай папку
      командой, потом пиши файл.
    - `read` режет очень большие файлы: используй `offset`/`limit`; `grep` и `glob` для поиска,
      а не `Select-String` и `Get-ChildItem -Recurse` (инструменты дают структурированный результат
      и не тратят вывод на форматирование).
    - git: пути длиннее 260 знаков дают `Filename too long`; пиши `git -c core.longpaths=true ...`.
      Исключение в pathspec - длинной формой `':(exclude)путь'`, короткая `':!путь'` на пути,
      который начинается с `_`, даёт `fatal: Unimplemented pathspec magic '_'`.
    - `curl` сам читает `[]` и `{}` в URL как шаблоны: пиши `curl -g ...` (код 3 «bad range
      specification», если не поставить).
    - `nvidia-smi --query-gpu=... -l 1 -f файл` пишет блоками по 4 КБ: при остановке хвост
      пропадает. Для лога на всё время прогона - короткий запрос раз в секунду в фоновом задании.
    - `taskkill /T /F /PID <pid>` гасит дерево процессов; в PowerShell ключи с `/` работают, в
      отличие от Git Bash.
    - Имена переменных PowerShell не различают регистр: `$game` затирает `$Game`. Не давай
      переменным имена, отличающиеся только регистром.
    - Свои локальные `.ps1` запускай через `& 'путь\скрипт.ps1'` или `powershell -NoProfile -File`;
      `-ExecutionPolicy Bypass` классификатор DSH может отклонить как ослабление защиты.

## Проверка результата
- `env_probe.py` без WARN, которые касаются вашей команды; после своего скрипта: файл существует,
  размер больше 0, в выводе нет `Traceback`.
- Для javap: сначала `javap -cp cp.jar известный.класс`, потом нужный. "class not found" бывает и
  при полном classpath: в 7 случаях из 7 (аудит 2026-10-15) виновато было имя (угаданный пакет,
  вложенный класс там, где на деле пакет), флаг после имени класса (тогда в ошибке стоит сам флаг:
  `class not found: -constants`) или относительный `-cp` после неудавшегося `cd`. Сверь имя: для jar
  `jar tf файл.jar | Select-String Имя`, для папки `Get-ChildItem -Recurse -Filter 'Имя*.class'`;
  вложенный класс бери в одинарные кавычки `'A$B'`; `-cp` давай абсолютным путём. Если класса нет в
  jar мода, он может лежать во вложенном jar `META-INF/jarjar/*.jar` (так у Sable 2.0.6 и Create
  Aeronautics bundled 1.3.2): распакуй вложенный jar во временную папку и добавь его в `-cp`.
- Для Python: вывод с не-ASCII символами печатается без ошибки (`-X utf8`), файл прочитан с
  `encoding='utf-8'`.

## Границы
- Файлы .bat/.cmd и вложенный в них PowerShell: `windows-shell-dev`.
- Если в проекте есть своя обёртка (например javap с готовым classpath), используй её, а не
  `classpath_jar.py`.
- Состояние проекта (версии модов, пути инструкций, статус работ) сюда не писать: это дневник
  проекта.
- Скрипты (у всех есть `--help`, только stdlib, вывод ASCII): `env_probe.py [папка]` (несуществующая
  папка даёт WARN, код всегда 0), `eol.py файлы` (MIXED или нечитаемый файл дают код 1),
  `classpath_jar.py out.jar вход... [--skip-missing]` (нет файла из списка, `@файла` или папки для
  out.jar: ошибка с кодом 1).

## Чего в этой версии нет
Прежняя версия навыка описывала стык Git Bash с Windows (пути `/c/...`, heredoc и лимит команды Bash
в 7,2 тыс. знаков, `unzip '*'`, `${PIPESTATUS}`, `MSYS_NO_PATHCONV`) - это ловушки Claude Code. В DSH
оболочка PowerShell, поэтому они не применяются и в порт не перенесены; они остались в исходном
репозитории `mamoru-claude-plugins`. Из той версии сохранены только ловушки, которые не зависят от
оболочки: python, JDK, classpath, CRLF, git, curl, кодировки.
